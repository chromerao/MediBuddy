# 메디버디 Design / UI 가이드

> 이 문서는 「아이디어개발기획서_콩닥」을 바탕으로 디자인/UI 담당 에이전트가 메디버디의 모바일 웹앱(PWA) 화면을 일관되게 설계·구현하기 위한 작업 지침이다.

## 1. 제품 한 줄 정의

**메디버디는 병원을 혼자 방문하는 중장년 만성질환자가 진료 전에 준비하고, 진료 중 질문을 놓치지 않으며, 진료 후 기억을 확인해 일상에서 실천하도록 돕는 AI 진료 동행 서비스다.**

의료진을 대신해 진단하거나 처방하지 않는다. 정보량이 많은 건강 대시보드도 아니다. 사용자가 짧은 진료를 잘 준비하고 이해하도록 돕는 **소통 보조 도구**다.

## 2. 디자인 목표와 우선순위

디자인 의사결정은 다음 순서를 따른다.

1. **이해 가능성:** 설명을 읽지 않아도 다음 행동이 보여야 한다.
2. **안전성:** AI의 추정과 의료진이 실제로 말한 내용을 혼동시키지 않는다.
3. **접근성:** 작은 글씨, 낮은 대비, 복잡한 제스처에 의존하지 않는다.
4. **안심감:** 녹음·개인정보 처리와 삭제 시점을 명확히 알린다.
5. **속도:** 진료실에서는 카드 확인과 녹음만 빠르게 실행할 수 있어야 한다.
6. **정서적 동행:** 겁을 주거나 채점당하는 느낌보다 차분하고 다정한 동반자처럼 느껴져야 한다.

## 3. 핵심 사용자

### 주 사용자

- 병원을 혼자 방문하는 50~70대 고혈압·당뇨 재진 환자
- 스마트폰 기본 조작은 가능하지만 긴 입력, 작은 글씨, 복잡한 메뉴에는 부담을 느낌
- 증상, 수치, 복약 정보나 의료진에게 물을 내용을 진료 중 빠뜨리기 쉬움
- 진료 후 설명을 정확히 기억했는지 확신하기 어려움

### 보조 사용자

- 멀리 사는 부모의 진료 준비를 돕는 성인 자녀
- 부모 대신 문진을 작성하고 질문 카드를 공유하거나 출력함
- 부모의 모든 정보에 무제한 접근하는 것이 아니라, 명시적으로 공유된 범위만 확인함

## 4. 경험 원칙

### 한 화면, 한 목적

- 화면마다 주 행동은 1개, 보조 행동은 최대 1개만 둔다.
- 한 화면에서 입력·분석·결과 확인을 동시에 요구하지 않는다.
- 긴 폼 대신 한 질문씩 진행하고 현재 단계를 보여준다.

### 말하기가 타이핑보다 먼저

- 증상과 수치 입력의 기본 CTA는 `말로 입력하기`다.
- 텍스트 입력은 항상 제공하되 보조 수단으로 배치한다.
- 녹음 중임을 색상만이 아니라 아이콘, 문구, 시간으로 함께 표시한다.

### 결과는 “한 장”으로

- 상태 카드는 의료진이 약 10초 안에 훑을 수 있도록 구성한다.
- 질문은 반드시 3개 이내로 번호와 함께 크게 표시한다.
- 인쇄·공유 시에도 카드 한 장의 정보 구조를 유지한다.

### 퀴즈는 시험이 아니라 기억 확인

- `점수`, `오답`, `틀렸습니다` 같은 표현은 피한다.
- `함께 다시 확인해요`, `이렇게 들으셨어요`처럼 교정 중심의 언어를 쓴다.
- 사용자가 답하지 못해도 실패 상태로 처리하지 않는다.

### 의료 안전을 UI에 드러내기

- AI 생성 정보에는 `진료 준비용` 또는 `AI가 정리한 내용` 라벨을 붙인다.
- 녹음에서 확인된 내용은 `진료에서 확인된 내용`으로 구분한다.
- 근거가 없거나 진단·처방 판단이 필요한 경우 답을 만들어내지 않고 `의료진에게 확인하세요`를 보여준다.
- 긴급 증상을 판별하는 서비스처럼 표현하지 않는다. 긴급 상황에는 119 또는 의료기관 연락을 안내한다.

## 5. 정보 구조

하단 내비게이션은 최대 3개로 제한한다.

1. **홈** — 다음 진료와 현재 해야 할 일
2. **의료수첩** — 진료 기록, 실천 항목, 한마디 수치 기록
3. **가족** — 가족 연결 및 공유 관리

설정, 개인정보, 도움말은 홈 상단의 프로필/더보기에서 접근한다. 진료 진행 중에는 하단 내비게이션을 숨겨 이탈을 막는다.

## 6. 핵심 사용자 흐름

### A. 최초 진입

1. 서비스 역할 설명
2. 직접 사용 / 가족 대신 준비 선택
3. 큰 글씨를 기본값으로 제공
4. 최소 정보 등록: 이름 또는 호칭, 관리 질환, 다음 진료일
5. 녹음 및 개인정보 정책은 실제 기능 사용 직전에 다시 설명하고 동의받음

온보딩은 3화면 이내로 끝낸다. 회원가입 방식의 상세 설계가 확정되지 않았다면 화면을 임의로 복잡하게 만들지 않는다.

### B. 진료 전 준비

1. 홈의 `진료 준비하기`
2. “최근 불편한 점이나 달라진 점을 말씀해 주세요”
3. 음성 또는 텍스트로 증상·경과 입력
4. AI 정리 결과를 원문과 함께 확인·수정
5. 상태 카드 1장과 질문 3개 생성
6. 저장, 가족 공유, 인쇄/큰 화면 보기

입력이 없고 진료일이 가까운 경우, 지난 기록을 바탕으로 만든 질문을 홈 카드에 제안하되 자동 확정하지 않는다.

### C. 진료 중

1. `진료 시작` 버튼
2. 녹음 동의 및 원본 자동 삭제 안내
3. 질문 카드와 큰 `녹음 시작` 버튼
4. 녹음 중에는 질문 3개, 녹음 시간, 종료 버튼만 표시
5. `진료 종료` 후 퀴즈 생성 대기

진료 중 화면에서는 AI 호출, 긴 메뉴, 기록 편집을 제공하지 않는다. 네트워크 불안정 시에도 질문 카드는 열려 있어야 한다.

### D. 진료 후 기억 확인

1. 한 번에 한 문항씩 짧은 확인 질문 제시
2. 선택형 또는 짧은 음성 답변
3. 문항별 즉시 채점보다 전체 응답 후 결과 제공
4. 결과를 다음 세 영역으로 고정
   - **잘 기억한 내용**
   - **다시 확인한 내용**
   - **진료에서 답을 못 들은 질문**
5. 원본 녹음 삭제 완료 안내
6. 확인된 지시사항을 실천 체크리스트로 저장

확신도가 낮은 STT 결과는 사실처럼 단정하지 말고, 사용자가 문장을 직접 확인하거나 의료진에게 문의하도록 한다.

### E. 일상 의료수첩

- 오늘의 실천 항목을 1~3개 중심으로 보여준다.
- `완료`는 넓은 체크 영역으로 제공한다.
- 혈압·혈당 등 수치는 `한마디로 기록`할 수 있게 한다. 예: “오늘 아침 공복 혈당 130”.
- 추세는 복잡한 분석보다 최근 기록과 변화 방향을 쉬운 말로 보여준다.
- 저장된 기록이 다음 진료 준비에 반영됨을 안내한다.

### F. 가족 대리 작성

1. 가족 초대 또는 연결
2. 누구를 위해 작성하는지 화면 상단에 지속 표시
3. 전화로 들은 부모의 증상과 수치를 대신 입력
4. 부모가 확인할 상태 카드·질문 3개 생성
5. 링크 공유 또는 한 장 인쇄

대리 작성 화면에는 `본인이 직접 말한 내용인지`, `가족이 대신 입력한 내용인지` 출처를 표시한다.

## 7. 필수 화면 목록

MVP 디자인은 아래 화면을 우선한다.

| 우선 | 화면 | 핵심 요소 | 대표 CTA |
|---|---|---|---|
| P0 | 시작/역할 선택 | 직접 사용, 가족 대신 준비 | 시작하기 |
| P0 | 홈 | 다음 진료, 준비 상태, 오늘 실천 | 진료 준비하기 |
| P0 | 증상 입력 | 큰 마이크, 실시간 전사, 텍스트 대안 | 말로 입력하기 |
| P0 | 입력 확인/수정 | 원문, AI 정리, 수정 가능 상태 | 이 내용으로 만들기 |
| P0 | 환자 상태 카드 | 증상, 경과, 복약/수치, 질문 3개 | 진료 시작 |
| P0 | 녹음 동의 | 사용 목적, 삭제 시점, 동의 | 동의하고 시작 |
| P0 | 진료 중 | 질문 3개, 녹음 상태, 경과 시간 | 진료 종료 |
| P0 | 처리 중 | 단계 안내, 이탈 방지, 실패 복구 | 백그라운드 처리/다시 시도 |
| P0 | 확인 퀴즈 | 한 문항, 큰 선택지, 음성 답변 | 다음 |
| P0 | 결과 | 정리·교정·누락, 녹음 삭제 완료 | 의료수첩에 저장 |
| P0 | 의료수첩 | 실천 체크, 진료 기록, 수치 입력 | 한마디로 기록 |
| P1 | 가족 목록/연결 | 공유 대상, 권한, 연결 상태 | 가족 초대 |
| P1 | 가족 대리 작성 | 대상 고정 표시, 입력 출처 | 질문 카드 보내기 |
| P1 | 카드 공유/인쇄 | 큰 글씨 한 장 미리보기 | 공유 또는 인쇄 |
| P1 | 기록 상세 | 당시 카드, 확인 결과, 실천 내역 | 다시 보기 |
| P1 | 설정/개인정보 | 글자 크기, 녹음 정책, 연결 해제 | 저장 |

본선 시연에서는 P0 흐름이 끊김 없이 한 사이클로 작동하는 것이 가장 중요하다. 외부 기기 연동, 건강 상담 챗봇, 보건소 연계 화면은 이번 범위에서 제외한다.

## 8. 홈 화면 구성

위에서 아래 순서로 배치한다.

1. 인사말과 프로필/사용 대상
2. 다음 진료 카드: 병원/진료일, D-day, 준비 상태
3. 상황별 주 CTA
   - 준비 전: `진료 준비하기`
   - 카드 생성 후: `질문 카드 보기`
   - 진료 당일: `진료 시작`
   - 진료 종료 후: `기억 확인하기`
4. 오늘의 실천 항목
5. 최근 한마디 기록

여러 기능을 동일한 크기의 카드 그리드로 나열하지 않는다. 현재 여정에 필요한 행동 하나가 가장 먼저 보여야 한다.

## 9. 상태 카드 규격

카드는 다음 순서를 고정한다.

- 환자 호칭, 관리 질환, 진료일
- **오늘 꼭 말씀드릴 점:** 핵심 증상 1~3개
- **최근 경과:** 언제부터, 빈도, 변화
- **복약·측정 수치:** 사용자가 입력한 사실만
- **의료진에게 물을 질문:** 번호가 있는 질문 3개
- 하단 라벨: `환자 입력을 AI가 진료 준비용으로 정리했습니다.`

빨강으로 위험도를 임의 판정하거나 상태를 정상/비정상으로 분류하지 않는다. 의료진용 진료기록처럼 전문용어를 늘어놓지 말고 환자의 표현을 유지한다.

## 10. 결과 화면 규격

세 영역의 의미와 시각 언어를 고정한다.

- **잘 기억한 내용:** 초록 계열 체크 아이콘. 과도한 축하 애니메이션은 사용하지 않는다.
- **다시 확인한 내용:** 주황/호박색 정보 아이콘. `틀림`이 아니라 정정된 내용을 먼저 보여준다.
- **답을 못 들은 질문:** 중립 회색 또는 파랑 계열 물음표. 다음 의료진 문의 항목으로 저장한다.

각 항목에는 가능하면 `진료에서 확인된 문장`과 `내가 기억한 내용`을 짧게 대비한다. STT 확신도가 낮다면 `녹음에서 명확히 확인되지 않았어요` 상태를 별도로 제공한다.

## 11. 비주얼 방향

### 브랜드 인상

키워드: **따뜻함, 안심, 명료함, 동행, 신뢰**

병원 EMR처럼 차갑고 빽빽한 화면, 유아적인 캐릭터 중심 화면, 게임형 점수판은 피한다. “콩닥”의 따뜻한 심장 박동 이미지를 은유로 활용할 수 있지만, 심박 이상이나 응급 상태를 뜻하는 의료 신호처럼 보이지 않게 단순하고 부드럽게 표현한다.

### 권장 색상 토큰

- `Primary 600`: `#176B68` — 주요 버튼, 핵심 강조
- `Primary 50`: `#EAF6F4` — 카드 배경, 선택 상태
- `Navy 900`: `#17324D` — 본문과 제목
- `Background`: `#F7FAF9` — 전체 배경
- `Surface`: `#FFFFFF` — 카드/패널
- `Success`: `#267A52` — 확인된 내용
- `Warning`: `#A85D00` — 다시 확인할 내용
- `Danger`: `#B42318` — 삭제/오류/긴급 안내에만 제한 사용
- `Border`: `#CBD8D5`

색상은 제안값이며 기존 브랜드 자산이 생기면 조정할 수 있다. 단, 모든 텍스트와 인터랙션은 WCAG AA 대비를 충족해야 하고 색상만으로 상태를 전달하지 않는다.

### 타이포그래피

- 한국어 본문은 가독성이 높은 산세리프(Noto Sans KR, Pretendard 등)를 사용한다.
- 기본 본문 18px, 최소 16px. 핵심 질문과 버튼은 20px 이상.
- 제목 26~32px, 줄간격 1.3~1.45.
- 본문 줄간격 1.55~1.7, 한 줄은 모바일 기준 지나치게 길지 않게 한다.
- 숫자와 단위는 붙여 읽기 쉽도록 표시한다. 예: `130 mg/dL`.

### 형태와 여백

- 모바일 우선, 기준 폭 360~430px.
- 8px 간격 체계를 사용하고 화면 좌우 여백은 최소 20px.
- 버튼 높이 최소 56px, 터치 영역 최소 48×48px.
- 카드 모서리 16px 내외, 그림자는 약하게 사용하고 경계선으로 구조를 명확히 한다.
- 주요 CTA는 화면 하단에서 쉽게 닿되 콘텐츠를 가리지 않게 sticky 영역으로 제공한다.

### 아이콘과 일러스트

- 아이콘은 선명하고 익숙한 형태를 사용하며 항상 텍스트 라벨을 함께 둔다.
- 마이크, 체크, 질문, 가족, 수첩 등 소수의 의미만 사용한다.
- 장식용 의료 십자, 주사기, 심전도 그래프의 남용을 피한다.

## 12. 핵심 컴포넌트

- `JourneyCard`: 다음 진료와 현재 단계 표시
- `PrimaryActionButton`: 아이콘+동사형 라벨, 최소 56px
- `VoiceInput`: 마이크, 녹음 상태, 시간, 일시정지/취소
- `TranscriptReview`: 사용자의 원문과 AI 정리문 비교·수정
- `PatientSummaryCard`: 한 장형 환자 상태 카드
- `QuestionCard`: 1/3 번호, 질문, 확인 체크
- `RecordingBanner`: 녹음 중/중단/저장 안 됨 상태
- `QuizCard`: 한 문항과 큰 선택지 또는 음성 답변
- `ResultSection`: 잘 기억함/다시 확인/누락
- `ActionChecklist`: 진료 지시에서 변환된 실천 항목
- `OnePhraseLog`: 음성 또는 단문 수치 입력
- `SourceBadge`: 환자 입력/가족 대리/진료에서 확인/AI 정리
- `SafetyNotice`: 의료진 확인, 응급 안내, 근거 부족
- `PrivacyReceipt`: 원본 녹음 삭제 완료 상태
- `FamilyContextBar`: 현재 대신 작성 중인 대상 고정 표시

각 컴포넌트는 기본, 로딩, 완료, 비활성, 오류 상태를 함께 설계한다.

## 13. 마이크로카피 원칙

- 쉬운 한국어와 짧은 능동형 문장을 사용한다.
- `제출`, `프로세싱`, `데이터`보다 `완료`, `정리 중`, `기록`을 쓴다.
- 사용자를 환자 번호나 질환명으로 부르지 않는다.
- 불안을 과장하지 않고 다음 행동을 함께 제시한다.

권장 예시:

- `최근 불편한 점을 편하게 말씀해 주세요.`
- `말씀하신 내용을 이렇게 정리했어요. 다른 부분이 있으면 고쳐 주세요.`
- `진료에서 꼭 물어볼 질문 3개예요.`
- `지금부터 진료 내용을 녹음해요. 기억 확인이 끝나면 원본은 바로 삭제돼요.`
- `틀린 답이에요` → `이 부분은 이렇게 다시 확인했어요.`
- `분석 실패` → `내용을 정리하지 못했어요. 녹음 상태를 확인하고 다시 시도해 주세요.`
- `근거 없음` → `이 내용은 메디버디가 판단할 수 없어요. 의료진에게 확인해 주세요.`

서비스 내 용어를 통일한다: `질문 카드`, `상태 카드`, `기억 확인`, `의료수첩`, `실천 항목`, `한마디 기록`.

## 14. 접근성 기준

- 브라우저 확대 200%에서도 주요 흐름을 완료할 수 있어야 한다.
- 본문은 사용자가 보통/크게/아주 크게 중 선택할 수 있게 한다.
- 스크린리더용 이름, 상태, 오류 설명을 제공한다.
- 키보드 포커스가 보이고 논리적 순서로 이동해야 한다.
- 자동 재생 음성이나 시간 제한 응답을 사용하지 않는다.
- 녹음 상태는 소리 없이도 알 수 있고, 진동/애니메이션에만 의존하지 않는다.
- 애니메이션은 짧고 절제하며 `prefers-reduced-motion`을 지원한다.
- 선택지는 충분히 떨어뜨리고 파괴적 동작은 확인 단계를 둔다.
- 인쇄용 질문 카드는 흑백에서도 구분되고 최소 14pt 이상을 유지한다.

## 15. 로딩·오류·빈 상태

### AI/STT 처리 중

- 막연한 스피너보다 `음성을 글로 바꾸는 중 → 질문을 정리하는 중`처럼 현재 단계를 알린다.
- 예상 시간이 길어지면 화면을 닫아도 처리되는지 명확히 안내한다.
- 동일 요청의 중복 실행을 막는다.

### 네트워크 오류

- 이미 생성된 질문 카드는 오프라인에서도 볼 수 있게 캐시한다.
- 녹음 업로드 실패 시 원본 삭제 여부와 재시도 가능 여부를 분명히 표시한다.
- 데이터가 사라진 것처럼 보이는 모호한 오류 문구를 쓰지 않는다.

### AI 근거 부족

- 빈 화면 대신 `의료진에게 확인할 질문`으로 전환할 수 있게 한다.
- 안전장치에 막힌 것을 시스템 고장처럼 표현하지 않는다.

### 기록 없음

- 첫 행동을 안내한다. 예: `아직 진료 기록이 없어요. 다음 진료를 준비해 볼까요?`

## 16. 개인정보와 동의 UX

- 녹음 전 **무엇을 위해**, **언제까지 처리하며**, **언제 삭제하는지** 짧고 명확하게 알린다.
- 동의 체크박스를 미리 선택하지 않는다.
- 퀴즈 완료 후 `원본 녹음이 삭제되었습니다`를 명시적으로 보여준다.
- 삭제 전·처리 중·삭제 완료 상태를 구분한다.
- 가족 공유는 대상, 범위, 기간을 보여주고 언제든 해제할 수 있게 한다.
- 실제 법률·정책 문구는 별도 검토가 필요하므로 디자인 시 확정된 법적 효력을 암시하지 않는다.

## 17. 반응형 및 PWA

- 핵심은 세로형 모바일 화면으로 설계한다.
- 태블릿/데스크톱에서는 콘텐츠 최대 폭을 약 720px로 제한한다.
- 가족 대리 작성 화면은 넓은 화면에서 입력과 카드 미리보기를 2열로 제공할 수 있다.
- 모바일 설치 유도는 첫 진입을 방해하지 않고 가치 경험 후 제안한다.
- 안전 영역(safe area), 모바일 키보드, 브라우저 하단 바를 고려해 CTA가 가려지지 않게 한다.

## 18. 프로토타입 및 구현 산출물

디자인/UI 담당 에이전트는 다음을 산출한다.

1. P0 전 화면의 모바일 고해상도 시안
2. 아래 2개 엔드투엔드 프로토타입
   - 당뇨 재진 환자의 직접 사용 흐름
   - 자녀가 부모 대신 진료를 준비하는 흐름
3. 색상·타입·간격·버튼·입력·카드·상태를 포함한 최소 디자인 토큰
4. 로딩, 빈 상태, 권한 거부, 네트워크 오류, STT 불확실, AI 근거 부족 상태
5. 상태 카드의 모바일/공유/인쇄 버전
6. 개발 전달용 컴포넌트 명세와 마이크로카피

## 19. 본선 시연용 핵심 시나리오

시연의 첫 번째 기준 시나리오는 다음과 같다.

1. 당뇨 재진 환자가 “요즘 새벽에 발이 저리고, 오늘 공복 혈당은 130이었어요”라고 말한다.
2. 메디버디가 이를 정리해 상태 카드와 질문 3개를 만든다.
3. 환자가 진료실에서 질문 카드를 열고 녹음을 시작한다.
4. 진료 종료 후 짧은 기억 확인 퀴즈에 답한다.
5. 서비스가 잘 기억한 내용, 다시 확인한 내용, 답을 못 들은 질문을 구분한다.
6. 원본 녹음 삭제 완료를 알린다.
7. 확인된 지시사항이 의료수첩의 실천 항목으로 저장된다.
8. 해당 기록이 다음 진료 준비에 반영되는 모습을 보여준다.

이 시나리오는 중간에 설명 없이도 관객이 현재 단계와 서비스 차별점인 **준비 → 기록 → 기억 확인 → 실천 → 다음 준비**의 순환을 이해할 수 있어야 한다.

## 20. 디자인 금지 사항

- 챗봇을 서비스의 메인 화면으로 만들지 않는다.
- AI가 진단, 처방, 위험도를 판정하는 듯한 문구나 UI를 만들지 않는다.
- 홈에 모든 기록과 그래프를 한꺼번에 보여주지 않는다.
- 작은 회색 글씨로 중요한 동의·삭제 정보를 숨기지 않는다.
- 질문 카드에 3개를 넘는 질문을 기본 노출하지 않는다.
- 점수, 순위, 연속 달성으로 건강 행동에 죄책감을 주지 않는다.
- 녹음 중임을 사용자가 잊을 수 있는 UI를 만들지 않는다.
- 가족 계정이 본인 동의 없이 전체 기록을 보는 것처럼 설계하지 않는다.
- 확정되지 않은 외부 기기, 챗봇, 보건소 연계를 MVP 핵심 화면에 넣지 않는다.

## 21. 디자인 완료 체크리스트

- [ ] 첫 화면에서 서비스의 역할을 한 문장으로 이해할 수 있는가?
- [ ] 각 화면의 가장 중요한 버튼이 3초 안에 보이는가?
- [ ] 본문 18px 기준이며 큰 글씨에서도 레이아웃이 깨지지 않는가?
- [ ] 모든 상태가 색상 외 아이콘과 문구로도 구분되는가?
- [ ] 질문 카드를 의료진이 약 10초 안에 훑을 수 있는가?
- [ ] 진료 중 화면이 질문 확인과 녹음에만 집중되어 있는가?
- [ ] 퀴즈가 시험이 아니라 안전한 기억 확인으로 느껴지는가?
- [ ] AI 정리, 환자 입력, 가족 대리 입력, 진료 확인 정보가 구분되는가?
- [ ] 녹음 동의와 삭제 완료가 명확히 보이는가?
- [ ] 오류 시 데이터 보존/삭제 상태와 다음 행동이 안내되는가?
- [ ] 직접 사용과 가족 대리 작성 흐름이 모두 완결되는가?
- [ ] 준비부터 다음 진료 반영까지 순환이 시각적으로 이어지는가?
- [ ] WCAG AA 수준의 대비와 키보드/스크린리더 기본 요건을 충족하는가?

디자인의 최종 성공 기준은 화면이 화려한지가 아니라, 스마트폰에 익숙하지 않은 사용자가 보호자 도움 없이도 **“지금 무엇을 해야 하는지”를 알고 진료 전·중·후 한 사이클을 끝낼 수 있는지**다.
